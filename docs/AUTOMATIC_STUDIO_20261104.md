서버 본문 렌더러가 그림을 일괄 누락한다는 가설은 확인되지 않았다. 격리된 PNG를 각 본문에 넣은 픽셀 검증에서 정상 합성을 확인했다. 실제로 확인한 기본값·노출·결과 갱신 문제를 수정했다.

## 사용자 작업 흐름

기본 메뉴는 **내 콘텐츠 / 수집함 / 발행함 / 설정**이다. 연결·실행 기록 등 운영 도구는 필요할 때 펼친다.

1. 채널을 고르고 새 콘텐츠의 제목·형식을 입력한다. 수집한 자료에서는 같은 원문·카드 편집 공간으로 이어진다.
2. 자동으로 원고·컷 구성의 빈 부분을 작성한다. 화면 진입이나 채널 추가만으로 유료 AI 요청이 발생하지 않는다.
3. 그림 단계에서 빈 컷만 생성하거나 선택한 컷만 다시 만든다. 장면·대사·구체적인 수정 지시를 같은 화면에서 입력한다.
4. 자동 생성 뒤에도 문구, 그림, 캡션을 직접 수정한다. 직접 수정하는 것은 수동 모드로 전환해야만 쓸 수 있는 기능이 아니다.
5. 저장된 그림과 최종 페이지를 확인한다. 미저장 편집이 있으면 이전 저장 버전의 미리보기라는 점을 표시한다.
6. 게시 계정·캡션·지금 게시/한국 시간 예약을 저장하고, 검토와 최종 승인을 거쳐 전송한다. 이미지 생성이나 승인 저장을 게시 성공으로 표시하지 않는다.

`WorkModeControl`의 자동·수동 구분은 실제 작업 방식에 적용한다. 수집·발행 화면에는 각 업무에 맞는 설명을 사용한다. 수동은 API 한도·연결 문제에서 기존 작업을 계속하는 경로이며, 자동 선택은 오류 때문에 임의로 바뀌지 않는다.

원문 기반 새 자동 초안은 기본 디자인이 글자 전용일 때 그림을 지원하는 기본 디자인을 선택한다. 명시적으로 선택한 디자인과 기존 콘텐츠의 디자인은 유지한다. 글자 전용 디자인은 화면에 설명하고 그림이 있는 디자인으로 바꾸는 버튼을 제공한다.

## 생성·미리보기 데이터 계약

### 직접 제작

- 기존 `studio_generate` 작업과 UUID `requestId`를 사용한다. 별도 Redis를 추가하지 않는다.
- `panelIndexes`는 중복 없는 1~4개 인덱스만 받는다. 한 작업에서 최대 네 컷을 순차 요청한다.
- 컷마다 이미지, 콘텐츠 revision, 작업 진행 상황을 같은 PostgreSQL 트랜잭션에 저장한다.
- 중간 실패·취소 이후에는 남은 요청을 중단하고 완료한 그림을 유지한다.
- 프로세스 재시작·lease 만료로 유료 생성을 자동 재호출하지 않는다. `maxAttempts=1`이다.
- 선택 컷의 문구 수정은 `textTarget: "panel"`을 사용한다. 다른 컷, 캡션, 제목, 기존 그림을 유지한다.
- 생성 중 원고가 바뀌면 늦은 결과를 현재 입력에 덮어쓰지 않는다. 미적용 revision으로 확인할 수 있게 남긴다.
- 기존 그림을 다시 그릴 때 참조 이미지로 전달하며, 이전 이미지 파일은 삭제하지 않는다.

### 원문 기반 카드

- 최초 자동 생성은 저장된 원고를 만든 뒤 이미지 생성으로 이어진다. 이미지 단계가 실패해도 원고는 이미 저장되어 계속 편집할 수 있다.
- `/items/:id/card`의 유료 생성 가능 경로는 `card_render` 작업 원장으로 기록한다. 옵션을 생략하는 이전 API 경로도 포함한다.
- 저장된 성공 응답은 같은 `requestId` 조회에 그대로 반환한다. 다른 원고를 같은 ID에 붙여 새 과금 요청으로 사용할 수 없다.
- item → Studio board → job 순서로 잠금을 획득하고 이미지·보드·재조회 응답을 같은 트랜잭션에서 저장한다.
- 취소나 다른 버전 저장이 먼저 확정되면 늦은 그림은 적용되지 않는다.
- 실행 기록에서 카드 이미지 작업 이름과 실행 중 중단 동작을 제공한다.
- 문구 재제안은 현재 저장 문구와 수정 지시를 참조한다. 선택한 카드만 적용하면 다른 카드의 문구와 카드 ID는 유지한다.
- 미리보기는 생성 API를 호출하지 않는다. 문구·페이지·저장 이미지가 바뀌면 기존 렌더러로만 다시 그린다.

AI 오류 안내는 인증, 미연결, 속도 제한, 크레딧·일일 한도, 과부하, 형식 오류, 결과 미확정, 취소를 구분한다. 공급자 메시지로 원인을 확정할 수 없으면 미확정으로 남긴다. 응답을 받지 못한 유료 요청의 과금 취소를 보장하지 않는다.

## 채널 계약

- 설정에서 이름, 고유 주소, 기본 콘텐츠 유형, 설명, 대상, 강조색, 소분류를 지정한다.
- 기본 유형은 `current_dialogue`다. 공지, 과학 자료, 직접 제작을 선택할 수 있다.
- 고유 주소는 생성 후 변경할 수 없다. 기존 alias·예약어·시크릿 환경변수 접두어 충돌을 검증한다.
- `channels.categories`의 `null`은 기존 기본 분류, `[]`는 분류 없음, 배열은 사용자 설정이다.
- 사용 중인 분류를 삭제하면 409로 반환한다. 분류 설정과 콘텐츠·검색어 배정의 동시 변경도 행 잠금으로 직렬화한다.
- 새 채널을 만들었다고 자동 수집·AI 생성·실제 게시가 즉시 시작되지는 않는다. 새 채널의 자동 발굴은 꺼져 있고 게시 한도는 0이다.
- 기존 네 브랜드의 이름·alias·계정 검증은 유지한다. 사용자 브랜드명은 고정 브랜드의 문자열 추측 규칙으로 바꾸지 않는다.
- 사용자 채널 Instagram 연결은 실제로 권한이 확인된 단일 계정만 선택한다. 복수 계정인 경우 임의로 골라 연결하지 않는다.

이 변경은 기존 운영 워크스페이스에서 여러 사용자 채널을 관리할 수 있게 확장한다. 서비스 판매를 위한 고객별 데이터 격리·역할 권한·결제 계약은 별도 설계와 검증이 필요하다. 채널 구분 자체가 고객 간 접근 통제를 뜻하지 않는다.

## 검증과 실행 방법

최종 전체 결과는 이 변경 PR의 CI와 첨부 artifact가 기준이다. 모의 응답으로 확인한 범위와 실제 외부 연동을 구분한다.

### 로컬에서 확인한 범위

- TypeScript 검사와 production build.
- React 입력·모드 전환·선택 카드 재제안·요청 ID의 콘텐츠별 격리·기기 복구 회귀.
- 6개 디자인 × 본문 4장의 실제 PNG 픽셀, 네컷 합성, ZIP 내부 PNG.
- Chromium 320/393/430/1280px에서 카드 수정·저장·재열기, 강제 종료 복구, AI 실패 후 입력 유지, 모의 즉시/예약·취소·재전송.
- Chromium 393/1280px에서 채널 전환·새 채널 추가, 자동 생성·기존 그림 보존·최종 여섯 페이지 decode.

### CI

```sh
npm run typecheck
npm test
npm run build
node scripts/mobile-regression.mjs
node scripts/content-workspace-regression.mjs
node scripts/channel-navigation-regression.mjs
node scripts/studio-automatic-regression.mjs
```

CI는 PostgreSQL 16과 WebKit을 사용한다. 로컬에서 WebKit이 없을 때만 `WORKSPACE_BROWSER_EXECUTABLE`로 Chromium을 지정할 수 있다. 결과 파일에는 실제 사용한 브라우저 엔진을 기록한다.

추가 PostgreSQL 검증은 `source-image-jobs-postgres`, `studio-image-batch`, `dynamic-channels-postgres`와 작업 복구·게시 준비·revision 복원 테스트에 있다. 중복 HTTP 요청, 중도 취소, 동시 편집, lease 만료, 분류 삭제/배정 경합을 다룬다.

모든 브라우저 회귀는 합성 데이터와 차단된 외부 요청을 사용한다. 실제 Instagram 게시, 운영 콘텐츠 삭제, 유료 AI 생성은 실행하지 않는다. 공급자 과금 계정에서의 실제 생성 성공과 외부 게시 성공은 이 테스트로 입증하지 않는다.

## 배포와 롤백

1. `0014_publication_intents.sql`, `0015_channel_categories.sql`은 nullable JSONB 컬럼을 추가한다. 기존 콘텐츠·이미지·전송 기록을 삭제하지 않는다.
2. CI 통과한 정확한 커밋만 병합한다. Render 자동 배포 후 `/api/health` revision과 DB 연결을 확인한다.
3. 실제 운영 화면은 읽기 전용으로 기본 모드·채널·미리보기 연결을 확인한다. 외부 게시와 유료 생성은 모의 검증 범위를 넘어 실행하지 않는다.
4. 인증 실패, DB 마이그레이션 실패, 지속적인 5xx, 기존 이미지 조회 실패, 입력 보존·전송 중복 방지 회귀가 나타나면 직전 애플리케이션 커밋으로 롤백한다.
5. 롤백 시 추가된 JSONB 컬럼과 작업 원장을 제거하지 않는다. 저장된 복구·게시 의도·생성 성공 증거를 유지해야 한다.

이미지 요청 동안 기존 렌더 트랜잭션이 DB 연결과 advisory lock을 보유하는 제한은 남아 있다. 현재 운영에서는 기존 PostgreSQL 작업 원장을 유지하고, 실제 동시 제작량과 작업 지연을 관측한 뒤 별도 worker 여부를 결정한다.
