# 채널별 AI와 8장 뉴스 편집 변경

기준: main `8914537766ac3f1c48a9b484b8c0ae29ea77e2be`. 운영 콘텐츠 28의 기존 저장본을 읽어 문제를 확인했고, 해당 콘텐츠를 자동으로 변경하거나 유료 생성·외부 게시를 실행하지 않았다.

## 사용하는 순서

1. 상단에서 채널을 선택하고 **설정 → 역할별 AI**에서 기사 요약·카드 문구·이미지의 공급자와 모델을 저장한다. 기존·신규 채널의 기본값은 Gemini / GPT / OpenAI 이미지다. 빈 모델 ID는 연결 설정의 현재 기본 모델을 사용한다. ChatGPT 구독은 OpenAI API 연결을 대신하지 않는다.
2. 뉴스 콘텐츠를 열고 **8장 뉴스 대화로 다시 구성**을 누른다. 원문 분석과 카드 문구 작성은 별도 역할로 실행된다. 기존 원고는 유지되며 제안이 먼저 표시된다.
3. **8장 제안을 편집기에 적용**한 뒤 각 페이지의 제목·부제·본문을 고친다. 두 시선과 개념 정의의 두 칸도 따로 편집한다. 선택한 카드만 다시 제안받는 기능도 유지한다.
4. 그림이 필요하면 해당 페이지의 **이 페이지 배경**을 펼친다. AI 그림 지시를 입력하거나 PNG·JPG·WebP 파일을 선택/붙여넣는다. 한 번에 선택한 페이지만 생성한다. 선명도 변경과 배경 제거도 가능하다.
5. 문구와 배경을 저장하고 **이미지 생성·갱신**으로 최종 8장 이미지를 만든다. 편집 미리보기와 최종 JPEG는 같은 렌더러를 사용한다. 최종 이미지·캡션·계정을 검토한 후 기존 즉시/예약 게시 흐름으로 진행한다.

기존 5장 저장본은 자동 변환하지 않는다. 공지·모집과 직접 제작의 다른 형식도 유지한다. 8장 구성은 기사 기반 뉴스 편집에 적용한다.

## 편집·복구 계약

- 요약은 사실/인물의 주장/미래 전망/해석과 원문 발췌를 구분한다. 인용문과 출처 ID가 실제 원문에 있는지 검사한다. 카드 작성에는 분석뿐 아니라 원문도 전달한다. 의미상의 정확성 전체를 자동으로 증명하는 검사는 아니므로 게시 전 검토가 필요하다.
- 원문이 없으면 8장 뉴스 작성 전에 중단한다. RSS 요약이나 제목만으로 새 뉴스를 만든다고 표시하지 않는다.
- 요약은 성공했으나 문구 작성이 실패하면 요약을 저장하고 부분 완료를 표시한다. 이미지 생성으로 자동 진행하지 않는다. 문구만 재작성하거나 직접 저장해 복구한다.
- AI 제안은 저장 전 검토 대상이다. 적용·저장할 때 검증된 작업 ID의 기사 분석과 실제 모델 기록을 새 리비전에 함께 보존한다. 기존 원문 요약 필드는 카드 문구 저장으로 교체하지 않는다.
- 원문을 다시 요약해도 이미 직접 편집한 카드 문구와 배경은 보존한다. 채널 설정을 바꿔도 이미 시작한 작업과 수집 실행은 기록한 공급자·모델을 사용한다.
- 배경 생성/업로드는 불변 이미지 자산을 만든다. 사용자가 선택하고 문구와 함께 저장해야 해당 카드 버전에 확정된다. 다른 콘텐츠의 자산 ID는 저장·보기·렌더링에서 거절한다.
- 업로드는 실제 픽셀을 검사하고 메타데이터를 제거한다. 파일은 8MB·4천만 화소 이하의 PNG/JPEG/WebP 정지 이미지로 제한한다. 외부 이미지 URL을 서버가 임의로 가져오지 않는다.
- 응답을 놓친 배경 요청은 읽기 전용 GET으로 결과를 찾는다. 브라우저 복구 기록에는 요청 UUID와 페이지·버전만 저장하며 이미지 base64를 넣지 않는다. 그 사이 원고가 바뀌었으면 새 배경을 자동 적용하지 않고 확인 후 사용할 수 있다.
- 페이지 미리보기는 선택한 배경 바이트만 읽는다. 단순 문구 저장은 이미지 전체를 DB에서 다시 내려받지 않고 소유권을 검사한다. 실제 렌더링에서는 저장 이미지 해시를 확인한다.
- 글자를 몰래 자르지 않는다. 수동 입력이 실제 공간을 넘으면 필드와 수정 안내를 보여 주며 원고는 남긴다. 기기 복구본은 역할·두 칸 문구·출처·배경·참고자료를 보존한다.

## 추가 활동의 참고자료

AI는 이 콘텐츠에 연결되고 본문이 확보된 자료의 ID만 선택한다. 제목·주소는 서버가 실제 원문에서 가져온다. 다른 콘텐츠의 자료나 변조된 제목·주소는 저장·미리보기·최종 렌더링에서 거절한다. 카드에는 참고자료 제목·호스트를 표시하고 편집기에는 실제 링크를 제공한다.

원문에 소개된 논문·과학관 등이 있으면 그 자료와 연결한 읽기·비교·관찰 활동을 제안할 수 있다. 해당 자료가 있다는 사실과 연구의 타당성·기관의 현재 운영 시간·방문 가능 여부를 확인했다는 주장은 구분한다. 외부 검색으로 새 자료를 찾았다고 표시하지 않는다. 연결된 근거가 없으면 원문 비교·주장 표시·자체 활동을 제안한다.

## 검증과 재현

- `npm run typecheck`, `npm test`, `npm run build`.
- CI는 실제 PostgreSQL 16에서 역할 설정의 CAS/채널 격리, 요청 UUID 재응답, 부분 실패, 원고 보존, 배경 자산 소유권, 취소/동시 수정, 검증된 참고자료를 검사한다.
- `node --import tsx scripts/news-editorial-regression.mjs`: 320·393·1280px WebKit에서 5장→8장 제안/적용, 두 칸 편집, 저장·재열기, 배경 업로드·붙여넣기, 최종 이미지·가로 넘침을 검사한다. API는 모의 응답, JPEG는 실제 제품 렌더러다.
- 기존 모바일, 단일 편집 화면, 채널 전환, 자동 이미지 브라우저 게이트도 함께 실행한다.
- `npx tsx scripts/render-news-editorial.ts`: 운영 28번의 기사 내용을 읽고 수동 작성한 제안으로 n03/n04의 실제 JPEG와 contact sheet를 만든다. 이는 유료 AI 생성 결과 또는 운영 콘텐츠 수정본이 아니다. [미리보기](assets/news-discussion8-preview.png).
- 외부 AI 모델의 계정별 접근 권한·실제 생성 품질·실제 Instagram 전송과 실기기 키보드/IME는 모의 응답 검증과 구분한다.

## 배포·회복 기준

전체 CI를 통과한 PR만 병합한다. main 병합 후 Render 자동 배포의 commit과 `live` 상태, `/api/health`, 설정의 세 역할, 기존 28번 콘텐츠 보존과 새 편집 동작을 읽기 전용으로 확인한다. 확인 과정에서 운영 생성·업로드·게시를 실행하지 않는다.

마이그레이션 `0016`은 채널 JSONB 열 추가만 수행한다. 데이터 삭제나 기존 콘텐츠 일괄 변환은 없다. 배포 실패 시 기존 서비스가 유지되는지 확인한다. **새 8장 원고가 저장된 뒤에는 구버전 편집기로 단순 롤백하지 않는다.** 구버전 스키마는 두 칸 문구·배경·참고자료 필드를 알지 못한다. 이 경우 새 데이터 읽기/보존 계약을 유지한 수정 배포를 우선하고, 생성 경로의 장애라면 해당 생성만 복구한다. 열이나 원고를 지워 복구하지 않는다.

디자인·편집 조사, 확인 시점과 라이선스 범위는 [조사 문서](NEWS_CARD_DESIGN_RESEARCH_20261104.md)에 기록했다. 외부 매체의 로고·사진·글꼴·코드를 복사하지 않았으며 닫는 표지는 채널 워드마크와 자체 대화 심볼을 사용한다.
