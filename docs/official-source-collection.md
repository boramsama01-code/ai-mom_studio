# 공식 출처 우선 수집 (2026-11-06)

HighScoop은 학교·기관의 모집 공고를 먼저 확인하고, ALLligodang은 기관의 연구·문화 발표를 먼저 확인한다. 네이버 뉴스·웹문서 검색은 새 소재와 독립적인 해설을 보완한다. Google 뉴스 RSS는 네이버 뉴스 경로가 실패했을 때만 사용하는 보조 경로다. 공식 목록을 읽는 것과 모집 접수 중임을 확인하는 것은 별개다.

정확한 URL·선택자는 `server/services/officialCatalog.ts`에 있다. 기존 운영자가 중지하거나 수정한 출처는 재시작 시 덮어쓰지 않는다. 교육청 검색은 교육부 현행 안내와 이전 지역명 검색을 함께 등록한다. 삭제·일시정지한 검색어도 다시 활성화하지 않는다. 초기 GED 설정이 원래 값 그대로인 경우에만 마이그레이션에서 10건을 100건으로 확장한다.

## 처리 순서와 한도

1. 마지막 확인이 오래된 공식 출처부터 읽는다. 소분류를 선택해도 해당 공식 출처를 읽는다.
2. 본문 확보에 호출을 남기도록 목록 요청은 대략 전체 호출 한도의 절반까지만 사용한다. GED 추가 페이지도 호출 한도에 포함한다.
3. 출처별 결과 한도를 나눈다. 새 공고, 본문 미확보 공고, 이미 처리한 공고 순서로 처리해 고정 공지가 새 공고를 가리지 않게 한다. 미처리 건은 다음 목록에도 남아 있어야 이어서 처리할 수 있다.
4. 뉴스 검색이 설정돼 있으면 전체 결과의 약 1/3을 보완 검색용으로 남긴다. 운영자가 설정한 한도를 늘리지는 않는다. 공식 출처가 하나 이상 응답하면 검색 호출은 HighScoop 최대 24회, 그 밖의 채널 최대 20회로 줄인다. 전부 실패하면 운영자가 설정한 기존 검색 한도를 사용한다.
5. 네이버 키가 없거나 인증·네트워크 오류가 발생하면 그 실행의 추가 네이버 요청을 중단한다. 뉴스만 공개 언론사 RSS·Google RSS로 보완한다. 웹문서·블로그는 실패로 기록한다. 성공한 네이버 검색이 0건이라는 이유로 Google 검색을 추가하지 않는다.
6. 출처를 번갈아 가며 각 출처의 첫 번째 원문부터 확보한다. URL 중복으로 기존 원고나 사용자의 수정 내용을 덮어쓰지 않는다.
7. 기존 자동 생성·알림·게시 설정을 그대로 따른다. 화면의 수동 수집은 기존처럼 자료 수집만 실행한다.

채용·임용·입찰·평가위원·대학생 전용 멘토 모집은 걸러낸다. 본문에 명시된 참가 대상이 초등학생·성인 등으로 확인되면 삭제하지 않고 제외 사유와 함께 보관한다. 대상이 불명확하면 확인 전 상태로 둔다. 링크·JSON의 글 등록일이나 목록의 날짜를 지원 마감일로 추정하지 않는다. 네이버 웹문서는 게시일을 제공하지 않으므로 게시일 미상으로 저장한다. 모집 공고의 접수 상태는 원문 확인 전까지 `unknown`이다. HWP/HWPX 등 자동 본문 추출을 지원하지 않는 첨부는 직접 확인 경로와 이유를 표시한다. 학교별 게시판의 첫 페이지 밖에 있거나 GED에 등록되지 않은 공고까지 전수 수집한다고 보장하지 않는다.

## 확인과 운영

- 규칙 → 수집 출처에서 마지막 목록 확인 시각, 정상/일부 처리/실패, 신규 건수, 오류를 볼 수 있다. 링커리어·공모전 사이트는 ‘발굴 사이트’로 표시하며 해당 도메인만으로 `official_confirmed`를 부여하지 않는다. 이 상태는 목록 수집 상태이며 개별 본문 추출 성공과 구분한다.
- ‘저장된 설정으로 게시판 시험 읽기’는 저장 없이 첫 목록을 확인한다. GED 전체 페이지를 읽지 않은 경우 범위를 표시한다.
- 실행 기록에는 공식 출처 수, 확인/실패/신규/중복과 한도로 남긴 건수가 기록된다.
- 예약 시각은 매일 한국 시간 08:00이다. ‘자동 수집 허용’이 켜져 있을 때만 자료를 수집하고, 꺼두면 예약 확인 후 수집을 건너뛴다. 예약 수집은 AI 작성·알림·게시를 실행하지 않는다. GitHub 예약 지연과 기관 서버 지연이 있을 수 있으며 실시간 푸시는 아니다. 즉시 확인은 수집 화면에서 실행한다.

## 검증

`npm run typecheck`, PostgreSQL을 사용하는 `npm test`, `npm run build`와 기존 브라우저 회귀 검사를 사용한다. 공식 목록의 실제 응답은 다음 읽기 전용 검사로 별도 확인한다. DB·AI 키나 게시 권한을 사용하지 않는다.

```sh
node --import tsx scripts/check-official-sources.ts
# 기관의 공개 HTML 구조를 확인할 때만:
node --import tsx scripts/check-official-sources.ts --inspect
```

외부 사이트 응답 검사는 기관 장애에 따라 실패할 수 있다. 실패했다고 CAPTCHA·로그인·접근 제한을 우회하거나 다른 문서를 해당 공고의 본문으로 대체하지 않는다.

## 근거와 제한

- 네이버 웹문서 API: https://api.ncloud-docs.com/docs/naver-api-hub-search-webkr (`sort=date`를 전송하지 않음, 게시일 필드 없음). 기존 개발자센터 키와 API HUB 키 지원을 유지한다.
- 교육부 지역 교육청 안내: https://www.moe.go.kr/sub/infoRenew.do?m=060104&page=060104&s=moe
- 직접 게시판 수집에 네이버 키는 필요하지 않다. 네이버 보완 검색은 ‘연결 설정’에 저장된 키와 검색 API 권한이 필요하다.
- 일부 기관은 첨부 문서만 게시하거나 동적 화면을 제공한다. 목록 성공은 본문 추출 성공을 뜻하지 않는다. 실제 실행의 출처별 오류와 날짜를 기준으로 판단한다.
- 본문 제외 규칙은 명시적인 대상 필드에만 적용한다. 참가 가능 여부·마감 상태를 완전 자동 판정하지 않으며, 나이·학년·지역 제한은 게시 전 원문 검토가 필요하다.
