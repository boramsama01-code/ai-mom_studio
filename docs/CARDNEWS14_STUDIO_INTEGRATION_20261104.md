## 변경 사항

### 1. 실제 14종의 8장 레이아웃

`shared/cardnews14Layout.json`은 전달된 `layout.json`에서 기사 예제·샘플 이미지 키를 제거한 신뢰된 배치 계약이다. 원본 14개 레이아웃은 `assets/cardnews14/layouts/`에 해시와 함께 보존한다. 112개 페이지에 총 644개 텍스트 박스와 89개 이미지 슬롯이 있다. 코드에 예제 기사 문구나 AI 예제 사진을 실제 기사 기본값으로 넣지 않는다.

각 페이지의 `elements` 순서를 그대로 그려 사진·그라데이션·선·장식·문구의 앞뒤 관계를 유지한다. 실제 Noto Sans KR/Noto Serif KR를 측정·그리며, 전달 파일의 Sans 호환 규칙에 따라 원본 굵기와 유효 굵기를 구분한다. 로컬 결과가 Canva의 글자 shaping과 픽셀 단위로 동일하다고 보증하지 않는다. 넘치는 문구는 필드별 오류로 알리며 자르거나 축소하지 않는다.

원본 앰버크림 1·4·7장의 얇은 하단선(y=1258)이 이미지 출처 영역(y=1248–1278)을 가로지르는 결함을 확인했다. 스튜디오에서는 해당 선 3개만 y=1290으로 옮겨 출처 아래 12px 간격을 확보한다. 문구·사진·다른 선·요소 순서는 유지한다. 전달받은 원본 `layout.json`, 원본 SHA와 Canva 디자인은 그대로 보존하고, 이 보정은 명시적 런타임 변환과 `-r2` 템플릿 버전으로 구분한다. Canva 자동 바인딩은 네이티브 원본에도 같은 보정을 적용하고 실제 8장 출력을 확인한 뒤에만 허용한다.

원본 이미지 키 B를 사용하는 슬롯은 흑백 처리를 선언한다. A/C 사진 슬롯에 흑백 처리를 일괄 적용하지 않는다. 사진 크롭·초점·밝기·모서리 처리는 Studio 미리보기와 Canva 업로드에 동일한 준비 함수를 사용한다. 고정 그라데이션·텍스트는 디자인 레이어이며 이미지에 중복 합성하지 않는다.

### 2. 장별 이미지와 표지 함께 사용

4/5/6/8개의 실제 슬롯에서 마지막 하나는 ALL 프로필이다. 기사 사진은 해당 스타일의 나머지 슬롯에서만 생성·교체할 수 있다. UI 안내, AI 장면 요청, 서버 검증에서 1·4·7장을 고정하지 않는다.

새 14종의 빈 내지 사진 슬롯은 `inheritCover:true`로 초기화한다. 표지 사진이 있으면 해당 장에서도 사용하며, 표지가 바뀌면 함께 바뀐다. 추가 AI 호출을 만들지 않는다. `resolvedReadingPageDesigns`가 미리보기·최종 출력·Canva 업로드에서 같은 결정을 내린다.

- 이미 선택한 페이지 사진이 있으면 그 사진을 우선한다.
- 사용자가 끈 `inheritCover:false`는 재생성 때도 유지한다.
- 각 장의 초점·크롭·밝기를 별도로 유지한다.
- 사진이 없는 장과 마지막 프로필 로고에는 상속을 적용하지 않는다.
- 사진창이 없는 스타일로 잠시 바꿔도 이전 함께 사용/해제 선택은 보존한다. 다시 사진창이 있는 스타일로 돌아오면 이전 선택을 적용한다. 슬롯이 없는 현재 페이지에 사진을 강제로 넣지는 않는다.
- ‘표지 사진 함께 사용’을 선택하면서 바꾼 이전 사진은 콘텐츠의 이미지 기록에 보존한다.
- 전달된 AI 예제 사진을 운영 콘텐츠에 자동 삽입하지 않는다.

AI 이미지 요청에는 실제 창의 가로세로 비율과 텍스트 중첩 영역을 전달한다. 전면 사진에 ‘글자용 여백이 필요 없다’고 지시하던 오류를 제거한다. 처음부터 모든 장의 이미지를 유료로 생성하는 흐름으로 바꾸지 않는다.

### 3. 문구 저장과 재생성

기존 의미 필드와 표시 문구의 단일 저장 기준을 유지한다. 기사 사실은 `fields`와 근거 연결에 저장하고, 출처·페이지 번호·시간 안내 등 표시값은 `displayOverrides`에서 수정한다. 고의로 비운 표시값도 AI 재생성·저장·재열기 때 보존한다. 스타일 선택은 기사 문구를 다시 작성하지 않는다.

인계의 46개 문자열은 최종 디자인 입력 계약이다. Studio는 제목·기사 사실 등 필수 의미 필드를 비운 상태로 승인할 수 있도록 검증을 완화하지 않았다. 미완성 입력은 기존 기기 복구본으로 보존하며 필수값 안내를 유지한다. 빈 표시값과 불완전한 기사 근거를 같은 상태로 취급하지 않는다. 문구 중간 단어를 따라가는 동적 형광펜도 이번 계약에 추가하지 않았다.

### 4. Canva 원본과 자동 제작 상태

`shared/cardnews14Catalog.ts`는 전달된 정확한 14개 source ID·링크를 표시한다. 디자인 설정에서 표지, 8장 샘플, Canva 원본을 볼 수 있다. `shared/readingCanvaMasters.ts`의 운영 허용 목록은 비어 있다. 후보를 추가했다고 `ready`로 승격하지 않는다.

이번에 실제 Canva `get-design`, `get-design-dataset`을 읽기 전용으로 다시 호출했다. 14종 모두 페이지 수 8, 텍스트 키 46개, 스타일별 이미지 키 4/5/6/8개가 코드 계약과 일치했다. 증거는 `docs/artifacts/cardnews14-live-datasets-20261104.json`에 저장한다. 계정 ID, 서명된 이미지 URL, 토큰은 기록하지 않는다.

이 확인은 Autofill 실행·8장 export 성공을 뜻하지 않는다. 전달 파일에는 계정 기능 권한 오류가 기록돼 있고, 복사·편집 대안도 표지 한 장만 추가 검증됐다. 실제 새 기사로 8장 생성·출력·검수한 뒤에만 원본 ID + 프로필 버전 + 매핑 버전 + 레이아웃/자산 SHA를 운영 허용 목록에 넣는다. Canva 마스터를 편집하거나 Brand Template으로 게시하지 않았다.

연결 상태 API는 계정 연결과 Autofill 기능 확인을 구분한다. 응답 누락·조회 실패는 `unknown`, 정상 응답에서 기능이 없는 경우만 `unavailable`이다. `missing_scope`, 디자인 접근 거부, 기능 미보유, 일시 호출 제한, 크레딧/작업 한도에 서로 다른 안내를 제공한다. 원본 오류 메시지나 임의 provider code는 노출하지 않는다. 응답을 못 받은 외부 POST의 결과 미확정·중복 재요청 차단은 유지한다.

### 5. 작업·출력 무결성

새 프로필의 `sourceLayoutSha256`/`sourceAssetsSha256`을 작업 스냅샷과 완료 결과에 보존한다. 다른 스타일이나 다른 레이아웃 버전을 같은 필드 수만으로 대체할 수 없다. 구형 작업에는 해당 값이 없을 수 있으므로 기존 두 스타일은 이전 계약을 계속 해석한다. 과거에 완료한 출력은 현재 프로필 목록이 바뀌었다는 이유만으로 무효화하지 않고, 저장된 입력과 출력의 대응을 검증한다.

### 6. 렌더링 비용과 동시 요청

원본 가변 폰트의 큰 변형 정보와 윤곽 처리 비용을 줄이기 위해, 같은 원본에서 실제 사용하는 굵기 7개를 정적 폰트로 만든다. 원본과 같은 전체 Unicode 범위를 보존하며 글자를 임의로 제외하지 않는다. 파싱한 폰트는 최대 5개, 반복 사용한 글자 윤곽은 폰트당 128개 항목·512,000 UTF-16 문자로 제한한다. 미리보기 사전 검사에서는 같은 글자 폭·줄바꿈·넘침만 확인하고 버릴 SVG 윤곽을 미리 만들지 않는다.

`opentype.js` 2.0.0의 무치환 조회에서 불필요하게 전체 문맥을 복사하는 부분만 수정한다. 설치·개발·테스트·빌드 시 원본/패치 SHA를 검사하며, 알 수 없는 버전이나 다른 소스이면 빌드를 멈춘다. CommonJS와 ESM 양쪽에 적용하고 MIT 고지를 동봉한다. 실제 Noto 7개 굵기와 기존 Pretendard 3개 굵기의 글리프 선택·폭·윤곽을 수정 전 라이브러리와 비교한다.

새 14종은 사진 변환 전에 페이지 작업을 접수하고, 이미지 변환 작업을 한 번에 하나씩 실행한다. 네이티브 SVG·픽셀 버퍼는 한 장을 처리하는 짧은 Node 워커에서 사용한 뒤 종료한다. 대기 포함 최대 4개를 접수하며 넘으면 원고를 보존하는 503 안내를 반환한다. 접수 시 30초 deadline을 기록하고 작업 시작 전·사진 준비 후 만료 여부를 검사한다. 네이티브 실행에는 남은 시간의 타이머를 적용한다. 네이티브 종료 확인을 기다리는 시간까지 포함해 HTTP 요청이 반드시 30초 이내 끝난다는 보장은 하지 않는다. 기존 두 스타일의 래스터 경로는 유지한다.

`node scripts/cardnews14-memory-qa.mjs --concurrent=2`는 실제 서버 모듈을 포함하는 배포 방식의 ESM 번들에서 기존 폰트·미리보기·8장 3회·동시 2요청을 실행한다. DB 연결, 공급자 호출, 강제 GC, 힙 제한은 사용하지 않는다. CI의 Node 22 결과는 `cardnews14-memory` 아티팩트에 남는다. 이 값은 명시된 원고·사진의 측정 결과이며 임의의 트래픽이나 이미지 크기까지 보장하는 용량 수치가 아니다.

2026-11-04 로컬 Node 22.23.4에서 같은 준비 검사·폰트 캐시·원고·사진·접수 제한을 사용한 비교 결과는 다음과 같다.

| 래스터 방식 | 최고 RSS | 전체 6요청 시간 | 실제 8장 결과 |
|---|---:|---:|---|
| 메인 프로세스 비동기 RGBA 변환 | 576.88 MiB | 10.09초 | 비교 기준 |
| 한 장씩 종료하는 워커 | 466.99 MiB | 12.84초 | 8장 SHA 모두 동일 |

시간에는 반복 사이의 짧은 대기도 포함하며 운영 서버 응답시간을 뜻하지 않는다. 워커 방식의 순차 3회 완료 RSS는 391.00·401.94·397.72 MiB였고, 동시 2요청 완료 후 활성·대기 워커는 0개였다. `render.yaml`의 free 설정에 대응하는 512 MiB와의 명목 차이는 약 45 MiB여서 실제 DB·수집 작업과 최대 크기 이미지 업로드가 겹치는 운영 여유를 확인해야 한다. 이 측정으로 512 MiB 운영 안전을 확정하지 않는다.

상세 증적은 `docs/artifacts/cardnews14-memory-20261104.json`에 있다. 글자 처리 수정 전후 동일 서체·최신 배치의 112 JPEG는 전부 동일했고, 기존 가변 서체에서 정적 서체로 바뀐 602개 대표 글리프는 윤곽 구성 차이 없이 116px 크기에서 최대 0.058px 좌표 차이가 있었다. 원본과 전체 Unicode 범위는 같다. 이는 Canva 출력의 픽셀 일치를 뜻하지 않는다.

## 운영자 사용 방법

1. 콘텐츠의 8장 편집기에서 **카드뉴스 스타일**을 선택한다. 기존 두 스타일도 남아 있다.
2. 표지 사진을 자동 생성하거나 직접 선택한다. 사진을 지원하는 내지는 **표지 사진 함께 사용**으로 채워진다.
3. 다른 장면이 필요한 장에서 함께 사용을 끄고 사진을 생성·업로드·붙여넣기한다. 직접 선택한 사진은 다른 장의 변경으로 바뀌지 않는다.
4. 각 장의 문구·출처·활동 안내를 수정하고 **문구·디자인 저장**을 누른다. 썸네일·선택 장 미리보기는 저장본/편집본 상태를 구분한다.
5. Canva 연결 또는 실행 검증이 끝나지 않았으면 기본 행동으로 표시되는 **스튜디오에서 8장 만들기**를 사용한다. Canva 출력이라고 표시하지 않는다.
6. 자동 채우기 권한이 확인되고 해당 스타일의 실제 출력 검증이 완료된 뒤 **Canva 8장 만들기**를 사용한다. 가져온 Canva 수정본은 8장을 모두 확인하고 문구 대조 후 새 버전으로 저장한다.

## 검증 범위

- 소스 계약: 원본 레이아웃·사진 SHA, 정확한 46개 키, 실제 14개 live dataset 대조.
- 이미지: 장별 상속·교체·수동 우선·마지막 로고 제외, 같은 준비 바이트 사용.
- 렌더: 14종 112페이지 실물 래스터, Noto font/weight, 레이어 순서, 문자열 누락·overflow 경계.
- UI: 스타일 변경·문구/빈 표시값·이미지 설정의 저장/재열기, 연결 확인 불가와 기능 미보유의 구분.
- PostgreSQL: 실제 DB를 사용하는 기존 Canva 복구·입력/출력 결속·취소 회귀와 새 hash 회귀를 CI에서 수행한다.
- 브라우저: 320/393/1280px 격리 API fixture에서 실제 카드 렌더러와 저장·재열기·사진 공유/해제를 확인한다. 외부 API는 모의 응답이며 실제 유료 AI나 Instagram 게시를 호출하지 않는다.

개별 실행 결과와 커밋의 CI 상태가 검증 완료의 근거다. 이 문서 자체가 운영 배포 완료를 보증하지 않는다.

## 재생성과 라이선스

`python scripts/import-cardnews14-layouts.py <풀어놓은 cardnews14_source_package 경로>`로 신뢰된 패키지에서 런타임 레이아웃을 재생성한다. 이 스크립트는 업로드된 임의 패키지를 운영 서버에서 실행하는 기능이 아니다.

Noto 원본 폰트는 SIL Open Font License 1.1에 따라 고지·라이선스·업스트림 해시를 동봉한다. 원본 가변 폰트 아카이브와 생성 방법을 보존하고, 실제 사용 굵기 7개의 정적 폰트를 무손실 gzip 조각에서 오프라인 복원해 해시를 검증한다. `scripts/build-cardnews14-static-fonts.py`와 `static-manifest.json`에 생성 도구 버전·전체 Unicode 범위·출처를 기록한다. 요청을 처리하는 중에 외부 폰트를 다운로드하지 않는다. 기존 Pretendard 파일과 라이선스는 그대로 유지한다.
