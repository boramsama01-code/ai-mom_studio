# 전면 사진형 카드뉴스: 요구 전환 명세
작성일: 2026-11-04
상태: 사용자 시각 방향 변경을 기록한 문서. 세부 스타일 선택·새 프로필 코드 구현·Canva 네이티브 등록·운영 배포는 미완료.

## 1. 이번에 확정된 방향

사용자는 기존 창형 A/B 시안이 원하는 인상과 맞지 않는다고 판단했고, 참고 레퍼런스처럼 **사진을 화면 전체에 깔고 큰 타이포그래피와 명암 그라데이션을 사용하는 방식**을 요청했다. 전면 사진 방식으로의 전환은 확정이다.

최종 매체는 Instagram 피드용 1080×1350px 카드 8장이다. 대상은 중·고등학생 자녀와 학부모이며, 뉴스의 사실·발언·전망·해석을 구분하고 서로의 근거·판단 기준·조건을 대등하게 나누는 기존 편집 원칙을 유지한다.

기존 창형 Ink/Lime·Cobalt/Paper는 이전 구현 기록으로 남긴다. 사용자에게 거절된 이 두 시안을 최종 Canva 마스터로 저장하거나 운영 등록·활성화하지 않는다.

## 2. 세 후보의 의미

| 후보 | 시각 방향 | 현재 상태 |
| --- | --- | --- |
| A · 시네마틱 | 전면 사진, 큰 제목, 명암 그라데이션으로 읽기 영역을 확보 | 추천 후보. 사용자 선택 미확정 |
| B · 흑백·코랄 | 흑백 사진과 코랄 포인트를 사용한 비교 방향 | 사용자 선택 미확정 |
| C · 앰버·크림 | 전면 사진에 앰버·크림 계열 강조를 사용한 비교 방향 | 사용자 선택 미확정 |

현재 완성한 비교물은 각 방향의 **표지·뉴스 읽기·STEP 2 래스터 비주얼 시안**이다. 이를 Canva 네이티브 요소·자동 채움 필드가 등록된 템플릿이나 구현된 Studio 스타일로 취급하지 않는다. 비교용 래스터 시안은 실제 운영 문구를 배경 사진에 굽는 제작 방식을 승인한 것이 아니다.

세부 팔레트, 제목·본문 좌표, 글꼴 크기와 줄 수, 그라데이션 방향·강도는 사용자가 세부 방향을 고른 뒤 실제 한글 문구로 확인해 확정한다.

## 3. 페이지 구성과 사진 처리

| 페이지 | 구성 | 새 시각 원칙 |
| --- | --- | --- |
| 1 | 표지 | 전체 배경 사진 위에 큰 제목. 제목 영역의 명암으로 대비 확보 |
| 2~3 | 뉴스 읽기 | 사진을 전체에 유지하며 본문 영역에는 어두운 오버레이·그라데이션 적용. 작은 뉴스 읽기 표기와 출처 유지 |
| 4 | STEP 1 | 전면 사진 위에 실제 상황·질문 배치 |
| 5 | STEP 2 | 전면 사진 위에 두 관점·판단 기준을 같은 무게로 배치 |
| 6 | STEP 3 | 전면 사진 위에 개념·정의·경계 사례·완성 문장 배치 |
| 7 | STEP 4 | 전면 사진 위에 활동과 도움말·시간을 배치 |
| 8 | 공통 마무리 | 기존 남색 #102D49, 밝은 왼쪽 정렬 문구, 승인된 ALL 프로필 한 번 |

1~7장에 ALL 로고를 반복하지 않는다. 문구가 바뀌어도 사진에 가려지지 않도록 텍스트 영역과 명암 처리 규칙을 함께 관리한다.

## 4. 새 데이터 계약: 텍스트 46개, 이미지 슬롯 8개

### 텍스트

기존 공유 resolver의 **46개 논리 텍스트 필드**를 유지한다. 제목·본문·관점·정의·활동뿐 아니라 뉴스 읽기·STEP·출처·페이지 번호·마지막 장의 문구와 계정도 Studio에서 확인하고 수동 수정할 수 있어야 한다.

사진은 글자가 없는 원본 이미지로 생성한다. 제목·본문·출처·STEP·로고를 AI 사진에 그려 넣지 않는다. 실제 Canva 결과는 별도 네이티브 텍스트 요소로 구성한다.

기존 V2 본문과 표시 전용 override의 분리, 수정값 보존, 잠금, 저장·다시 열기·AI 부분 재생성 보호를 유지한다. 같은 본문을 새로운 Canva 전용 필드에 중복 저장하지 않는다.

### 이미지

새 요구의 8개 이미지 슬롯은 다음과 같다.

- 1~7장: 페이지마다 독립된 1080×1350 전체 배경 이미지 슬롯 1개씩.
- 8장: 승인된 ALL 프로필 이미지 슬롯 1개.

**사진 원본 수와 출력 슬롯 수는 다르다.** 기본 운영은 Studio에서 생성한 공통 원본 사진 한 장을 1~7장에 재사용하는 방식이다. 페이지마다 크롭·초점·밝기·오버레이·그라데이션을 적용할 수 있지만, 슬롯이 7개라는 이유로 AI 이미지를 일곱 번 생성하지 않는다.

같은 원본을 여러 Canva 요소에 전달할 때는 각 페이지의 확인된 필드로 명시적으로 주입한다. 단일 autofill 필드를 여러 페이지에 반복 지정하는 동작에 의존하지 않는다. 기존 네 이미지 필드명과의 호환 여부, 추가 배경 필드명과 정확한 이미지 타입은 새 네이티브 템플릿 제작 때 확정한다.

## 5. 구현할 때 공유해야 할 동작

다음은 **후속 구현 요구**이며 이번 문서 변경으로 구현된 사항이 아니다.

1. 새 전체 배경 프로필에 별도 templateKey·templateVersion·mappingVersion을 부여한다. 과거 창형 키가 새 배치를 가리키도록 덮어쓰지 않는다.
2. 공통 원본 사진과 각 페이지의 처리 설정을 해석하는 한 함수를 Studio 미리보기·Canva 이미지 준비·사진 출처 표시에서 사용한다.
3. 크롭·밝기·명암 그라데이션을 적용한 같은 배경 바이트를 Studio와 Canva에 전달한다. 원본 사진은 그대로 보관하고, 텍스트는 배경 처리에서 분리한다.
4. 사진 → 명암·강조 요소 → 네이티브 텍스트 순서와 실제 한글 줄바꿈을 확인한다. 2~3장 본문은 긴 문단 전체의 대비를 검사한다.
5. 기존 고정 크기·명시적 줄바꿈·maxLines 검사를 새 좌표에 적용한다. 문구가 넘치면 해당 필드를 표시한다.
6. 기존 “고정 사진창”, “제목 여백 불필요”, “텍스트는 사진 밖” 지시는 새 전면 사진용 이미지 브리프와 안내로 교체한다. 모델·API 설정 변경은 이 요구에 포함하지 않는다.

기존 `expectedCanvaDataset()`과 이미지 준비 경로는 프로필의 이미지 슬롯 목록을 순회한다. 새 8슬롯 계약을 선언한 뒤 실제 데이터셋·출력과 일치하는지 검증해야 한다. 기존 창형의 46/4 테스트 통과는 새 전체 배경의 46/8 구현 완료 증거가 아니다.

## 6. 승인·등록 상태

- PR64에는 기존 창형과 전체 문구 편집을 위한 코드가 별도 작업 브랜치에 있다. 이 문서 갱신은 코드·가드·모델·CI 설정·배포를 변경하지 않는다.
- 기존 창형 A/B의 최종 Canva 저장·운영 활성화는 하지 않았다.
- `shared/readingCanvaMasters.ts`의 승인 sourceId 목록은 비어 있으며 유지한다.
- 전면 사진 방식은 확정됐지만 A/B/C 중 세부 스타일은 미확정이다.
- 세 래스터 시안을 실제 8장 네이티브 템플릿 등록이나 실계정 자동 채움 완료로 표현하지 않는다.

다음 단계는 세부 시안 선택, 8장 네이티브 제작 및 Studio 프로필 구현, 실제 46개 텍스트·8개 이미지 필드와 페이지 순서 검증, 승인된 sourceId 연결이다. 실제 이미지 생성·업로드·자동 채움·8장 출력·재수입과 운영 배포 여부는 그때 확인한 증거로 별도 기록한다.

## 7. 이전 기록과의 관계

[기존 구현 인계문서](CANVA_STUDIO_DISPLAY_HANDOFF_20261104.md)는 수동 문구 보존·공유 resolver·복구·이전 창형 코드의 근거로 남긴다. 그 문서의 창형 색 면·고정 사진창·46/4 시각 계약을 현재 요구로 적용하지 않는다.

`docs/artifacts/reading-template-canva-manifest.json`도 이전 창형 시안의 복구 기록이다. 새 전면형 템플릿의 승인 목록이나 준비 완료 데이터로 사용하지 않는다.
